## 各维度：做了什么 → 缺什么 → 怎么补分

### 1️⃣ 技术可行性（20 → 目标 18+）
**已有**：本地 BERT 感知、BM25（字符 bigram）纯 CPU、离线 geocoder(DataV)、LightGBM 归口基线 Top-1 50.6%/Top-3 80.7%；云端 LLM 秒级，q 门控采样；harness 白名单/预算/超时防失控。
**缺/弱**：无自动化回归/评测一键脚本的 README 口子；容错靠兜底（无优雅降级说明）。
**补分动作**：
- 方案里写清"一条 1 秒内出结论、无 GPU 也能演示、成本 <0.1 元/条"。
- 提供 `scripts/` 一键复现（评测已有 eval_dept_33w.py 等），突出"每个能力都有可量化指标"。

### 2️⃣ 市场可行性（20 → 目标 15+）
**已有**：泛用性——城市/区县两级 + 23 类职能映射 + 跨城可迁移；能力集成度高（对话/看板/地图/风险/检索/批量/月报/多模态）；高度契合政务"留言→归口→回复→复核"真实业务链。
**缺/弱**：**商业模式/客户/落地路径缺表述**（就业 demo 常被问"谁买单、怎么落地"）。
**补分动作**：
- 补一段话术：目标客户=省市/区县"12345 热线 + 基层治理办"；价值=减人工归口工作量、防回复幻觉舆情、月报自动产出；SaaS/私有化部署定价逻辑。
- 演示用**真实区县/部门**（临沂案例正确落到 兰山区城管），突出"开箱即用已有 642 区县底座"。

### 3️⃣ 综合创新性（20 → 目标 17+）
**已有（三大原创点，已在代码落地）**：
1. **Adaptive Retrieval**：按信息充分性 decide retrieve/deepen/skip，非"无脑固定 RAG"。
2. **Evidence-based Decision**：强制引用真实案例+**真实政策条款**（引用溯源校验剔除编造）。
3. **Governance Quality Gate**：self-consistency 投票→pass/retry/escalate，一致性低自动转人工。
**缺/弱**：概念创新/产品创新的**对外表述**未整理成一句卖点；政策库是种子规模。
**补分动作**：
- 一句话创新叙事："让 AI 在政务回复里『引用真法条、只引用检索到的东西』——防幻觉用约束+校验而非碰运气"。
- 扩容政策库（本迭代已建 24 部真实法规，后续按留言高发主题扩到 50+）。

### 4️⃣ AI 大模型结合（20 → 目标 17+）
**已有**：**plan→execute→replan→gate** 全程 LLM；DeepSeek 做规划/分析/决策/记忆/重答；kimi 多模态识图进完整管线；SSE 实时思维链；LLM 结构化输出容错。
**缺/弱**：提交的"创意描述"里要有**图文/流程细节**展示大模型在哪个环节怎么用。
**补分动作**：
- 提交附**一张流程图**（节点：留言→感知[本地]→分析[LLM]→自适应检索[BM25]→政策检索→决策[LLM,引用真条款]→质量门控[LLM×3投票]→人工复核）。
- 强调降本技巧：感知用本地小模型、仅核心判断走 LLM、门控可关、单条成本可算。

### 5️⃣ 赛道维度评定（20 → 目标 17+）
子项：
1. **任务理解与自主规划**：planner 把模糊诉求拆成动作序列 + replan 动态插 geo/政策检索 + 自适应检索。✅强
2. **工具调用与环境交互**：不是问答机器人——能 retrieve/geo_query/stats/mcp_call(模型跑水涝/交通)/调 VLM 识图。✅强（演示重点）
3. **结果交付与可验收**：decision 含 责任部门/措施/政策依据/参考案例/80字回复/风险提示，证据可点击，门控通过才定稿。✅较完整
4. **场景价值与端到端闭环**：一张留言→地图定位→归口→引用政策→生成可回复建议→质量门控→历史可回放。✅强
**缺/弱**：缺"一键交付物"感（数字员工输出的成品没有导出/工单形态）；回放历史较简陋。
**补分动作（已完成本轮）**：
- ✅ **工单生成（todo#2 落地）**：`app/agents/work_order.py` 把留言+决策组装成标准处理工单（编号/类型/领域/区域/紧急度/风险/归口/承办/办理时限/处置措施/政策依据/参考案例/面向市民回复/复核），**字段完整率 100%**；前端聊天结果顶部展示「📋 处理工单」卡片（可**复制 Markdown / 下载 JSON**），每次对话/图片分析都产出可验收交付物。
- 历史记录**忠实重放**原始决策全文+地点+轨迹，修复"串位/截断/地图残留"——让"可验收交付物"可回溯。
- 后续把工单接进历史回放 + 字段完整率评测脚本（≥95% claim）。

## 建议的演示脚本（60~90 秒，命中 5 个维度）
1. 输入一条含地点+明确问题的留言（如临沂污水外溢）→ 看计划拆解、自适应检索、**政策真实引用**（评审最惊讶点）。
2. 打开右侧**地图**精准定位到 临沂兰山区（回应"工具交互/环境"）。
3. 演示**历史记录重放**与上一条完全相同（回应"可交付/可回溯"）。
4. 展示**质量门控**：一致性低时自动"转人工复核"（回应"可信治理"）。
5. 收尾一句话：数字员工把"群众留言→责任部门→有据可依的回复→复核"闭环做完。

## 下一步优先级（对应 PROGRESS 待办）
1. **工单生成**（字段完整率≥95%）→ 赛道 3/4 最加分（数字员工可交付物）。
2. **评测体系**（人工标注+recall@5+幻觉率+消融）→ 技术可行性 + 论文双产出。
3. **政策库扩容 + 市场/商业模式文字** → 市场可行性 + 创新性表述。
