## 二、逐页大纲（建议 12~15 页，路演 8~10 分钟）

### P1 封面
- 标题：**城市治理 Copilot**
- 副标题：**让每一条群众留言，都有据可依、有人可办、可被验收**
- 角标：人民网留言板 2025 · 33.3 万条真实民情 · 多智能体
- 【图1】**封面主视觉**：一张"留言 → 工单"的抽象数据流背景（深蓝渐变 + 城市天际线剪影 + 一条从"市民气泡"流向"工单卡片"的光带）。风格：科技政务、留白多。
- 维度：开场印象

### P2 一页看懂：我们在解决什么
- 痛点三连：**归口靠人翻条例**（慢）· **回复怕说错/编造**（险）· **办没办、办得怎样**（散）
- 一句话方案：把"群众留言 → 责任部门 → 有据可依的回复 → 可验收工单 → 复核留痕"整条链交给一个**可控的多智能体**。
- 关键差异：**不是聊天机器人，是数字员工**；**不编法条，只引真条款**。
- 【图2】**痛点→方案对照图**：左侧三个红色痛点图标，中间箭头汇聚到一个蓝色"Copilot"中枢，右侧输出"工单/回复/地图/预警"。左右对照式排版。
- 维度：市场可行性、综合创新性

### P3 现场能做什么（真实场景）
- 3 个并列场景卡片（用真实截图或示意）：
  1. **一句话留言 → 自动归口 + 引用法条 + 生成回复**
  2. **上传现场照片 → 识图（地点/问题/对象）→ 走完整管线**
  3. **一张工单直接可下载**（编号/承办/时限/政策依据）
- 【图3】**三张产品截图拼版**：左=对话结果卡（含"政策依据"真实条款与可点案例）；中=图片识别结果（规整分点）；右=工单卡片（可复制/导出）。若暂无截图可先做**界面示意稿**。
- 维度：市场可行性、赛道维度（结果交付）

### P4 一条留言的 30 秒旅程（端到端闭环）
- 闭环链：**感知(本地) → 分析 → 自适应检索案例 → 政策检索 → 决策 → 质量门控 → 工单/回复 → 人工复核 → 留痕**
- 两个标注：每一步是"本地小模型/检索/大模型"，以及大致耗时。
- 强调：**全链路可回放、可审计**（trace 落库）。
- 【图4】**横向泳道流程图（最重要的一张图）**：8 个节点从左到右；节点下方用小标签标注"本地/BM25/大模型(kimi/DeepSeek)/规则"；顶部一条"审计留痕"的横条贯穿；右下角标"总计 <30s"。
- 维度：赛道维度（自主规划/闭环）、AI大模型结合、技术可行性

### P5 会"看情况"地干活（不是无脑检索）
- 反差：**固定 RAG** 无论需不需要都检索、检索了也照单全收 → **我们的 Agent 会先判断"信息够不够"**。
- 三种决策：信息不足→**去检索**；检索质量差→**换词再挖一次（限 1 次）**；证据充分→**跳过**。
- 【图5】**"固定RAG vs 自适应检索"对比图**：左（灰）固定流程死板直线；右（蓝）带判断分叉的流程（三岔：retrieve/deepen/skip）。旁边小字标"决策依据：分类置信度/地点/部门置信度/案例质量"。
- 维度：综合创新性、技术可行性、赛道维度（自主规划）

### P6 它会"动手"：工具与模型调用
- 一句话立场：**区别于问答机器人的关键 = 能调动外部资源完成"行动"**。
- 调用了什么：案例检索(BM25) · **政策库检索** · 空间分析(geocoder+邻近案例) · 数据统计(33万) · **MCP 外部模型工具**（洪水/交通/生活圈模型）· 多模态 VLM 识图 · 文本/表格分析。
- 【图6】**"工具能力矩阵"图**：一组工具图标排成九宫格/环形，中间是 Agent；每格标工具名 + 一行"能完成什么行动"；用亮色突出"政策检索""MCP模型""VLM识图"。
- 维度：赛道维度（工具调用与环境交互）、AI大模型结合

### P7 它敢引用哪一条法？（Evidence-based，反编造）
- 问题：政务回复**编造法条 = 红线**。
- 做法三步：
  1. 建**真实政策库**（24 部法规 / 44 条款，含发文机关、施行日期）
  2. **条款级检索**按诉求召回相关条款
  3. 决策**只允许引用检索到的真实条款**；**后处理溯源校验，对不上的引用直接剔除并告警**
- 效果举例：某工地扬尘诉求 → 引用《大气污染防治法》第八十一条 等真实条款。
- 【图7】**"反编造三闸门"示意图**：一条从"大模型拟引用"到"进入正式回复"的管道，中间三道闸门（①只能从真实库选 ②条款级匹配 ③溯源校验不一致即剔除），被剔除的引用用红色叉号飘出。
- 维度：综合创新性、技术可行性、赛道维度（结果交付）

### P8 三个"大脑"投票，拿不准就转人工
- 机制：对决策的关键字段**多次采样投票**，一致性高→通过；中等→**重写**；低→**升级人工复核**。
- 价值：**政务要的不是"敢答"，而是"该慎重时慎重"**。
- 【图8】**"投票门控"仪表图**：中间一个仪表盘/三格计分（一致性 0~1），三个区间用绿/黄/红（通过/重写/转人工）；旁边画出 3 个采样气泡汇聚投票。
- 维度：综合创新性、赛道维度（闭环）、市场可行性（可信）

### P9 交付的不是"答案"，是一张工单
- 工单字段：编号 / 类别领域 / 事发区域 / 紧急度 / 风险 / **归口部门** / 承办 / **办理时限** / 处置措施 / **政策依据** / 参考案例 / 面向市民回复 / 复核状态。
- 关键指标：**关键字段完整率 100%**（确定性派生 + 兜底，不依赖大模型每次都吐全）。
- 可**复制 / 下载 JSON**，可直接进办理流程。
- 【图9】**工单卡片设计图**：一张仿真"政务处理工单"卡片，字段分两列宫格排布，右上角盖一个"字段完整率 100%"的绿色徽章；旁边一条"复制/下载"按钮示意。
- 维度：赛道维度（结果交付与可验收性）★最吃这张

### P10 大模型到底用在哪、怎么用（必须讲清环节细节）
- 逐环节说明（这是评分明确要求的"大模型环节流程细节"）：
  | 环节 | 用没用大模型 | 用什么 | 怎么用/怎么降级 |
  |---|---|---|---|
  | 感知分类 | 否 | 本地 BERT | 省 token、CPU 毫秒级 |
  | 实体/诉求分析 | 是 | DeepSeek | 结构化抽取；失败重试+兜底 |
  | 规划 Planner | 是 | DeepSeek | 产出动作序列；运行时字段不可被 LLM 篡改 |
  | 政策/案例检索 | 否 | BM25 | 纯 CPU、可离线 |
  | 决策生成 | 是 | DeepSeek×3(投票) | 结构化 JSON + 证据约束 + 解析容错 |
  | 现场识图 | 是 | kimi 多模态 | 识图→当留言走完整管线 |
  | 面向市民回复 | 是 | 可切换本地 Qwen | 双线可切，失败回退云端 |
- 【图10】**"大模型环节地图"图**：把 P4 的流程放大，凡"用大模型"的节点标蓝色机器人图标、未用的标灰色芯片图标；配一个"成本/耗时"小标注。
- 维度：AI大模型结合 ★本维度直接对应

### P11 没有 GPU 也能跑：数据底座与成本
- 数据：33.3 万条真实留言；1200 条 LLM 标注；**33 万免费现成标签**（回复组织 29.5 万、满意情况 5.9 万）；642 区县位置底座。
- 工程：离线 BM25/规则/geocoder；云端大模型秒级；**单条成本 <0.1 元**；**端到端 <30s**；动作白名单+预算+超时。
- 【图11】**"数据底座金字塔"图**：底层 33 万原始留言，中层"免费标签/1200标注/区县底座"，顶层"多智能体能力"；右侧一条"成本 & 耗时"标尺。
- 维度：技术可行性 ★本维度直接对应

### P12 我们的数字，和我们的边界（诚实）
- 已出数字：机构名归口 Top-1 1.7%（类别爆炸不可学）→ 职能检索式 **37.6%**；33 万 LightGBM **Top-1 50.6% / Top-3 80.7%**；质量门控低一致性自动转人工。
- 明确边界（**主动说出短板**，评委反而加分）：归口准确率仍未达 90%；**人工标注 Benchmark / recall@5 / 幻觉率 / 消融实验** 正在补。
- 【图12】**"进度条/雷达"双图**：左=已达标项（绿）与在建项（黄）的进度条；右=一张留白的雷达图，标注"下一阶段补齐：benchmark/幻觉率/消融"。
- 维度：技术可行性、综合创新性（诚信与工程素养）

### P13 谁能用、怎么落地
- 客户：省/市/区县 **12345 热线、基层治理办、信访/督查部门**。
- 价值：**减人工归口工作量** · **防回复幻觉舆情风险** · **月报/工单自动产出** · 全流程留痕可问责。
- 模式：SaaS 订阅 / 私有化部署（政务云），按坐席或按量；已有 642 区县底座可**开箱即用**。
- 竞争差异：多数同类是"通用问答/RAG demo"，我们是**"政务闭环 + 反编造 + 可验收工单"**。
- 【图13】**"落地路径图"**：三级火箭——试点区县 → 市级推广 → 平台化 SaaS；旁边配"客户画像"小卡与"成本-收益"简图。
- 维度：市场可行性 ★本维度直接对应

### P14 越用越聪明（可控的数据飞轮）
- 飞轮：**运行留痕 → 人工复核（采纳/修改/驳回）→ 优质样本回流 → 周期重训 → 评测门控 → 灰度上线**。
- 关键态度：**不做"自己训自己"的失控进化**；只学"被人工认可"的样本，且必须过评测门控。
- 当前进度：留痕(trace)已落地；复核落库与偏好数据集**规划中**。
- 【图14】**"数据飞轮"圆形循环图**：6 个环节绕圈，中心写"人的确认"；圈外标一条"评测门控=闸门"，强调"不合格不进环"。
- 维度：综合创新性、市场可行性（长期价值）

### P15 收尾
- 一句话：**让城市治理的每一次回应，都有据、有责、可验收。**
- 团队 / 下一步（补评测体系、扩政策库、飞轮闭环）/ 联系方式。
- 【图15】**结尾页**：与 P1 呼应的极简视觉（城市光带闭合 + 一句话标语）。
- 维度：全场收束

## 四、路演节奏（8~10 分钟）
- P1–P3（1.5 min）**30 秒讲清价值**，别急着讲技术。
- P4–P9（4 min）**对着流程图和工单讲闭环**——这是评委最想看的"完整链路 + 可交付物"。
- P10（1 min）**专门交代大模型用在哪**（评分硬要求）。
- P11–P13（2 min）数字、边界、市场。
- P14–P15（1 min）飞轮与收尾。
- 备好 1 个**真实 demo**（政策引用 + 工单导出）随时点开，比 PPT 更有说服力。
