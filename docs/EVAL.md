# 评测报告 · 归口预测基线（v0.3）

> 更新：2026-08-15 深夜（v0.3：BERT v3 Kaggle 5 折结果）· 数据：data/labeled_1200.csv · 纯本地/免费

## 结论速览

| 粒度/版本 | Top-1 / acc | Top-3 / macroF1 | 说明 |
|---|---|---|---|
| 机构名（回复组织原值） | 1.7% | 2.8% | 854 类，84.8% 单例 → **小样本下数学上不可学** |
| 职能 v1（粗映射 20 类） | 24.2% | 60.9% | 关键词规则覆盖 74.6%，"其他"270 条是大杂烩 |
| **职能 v2（修复映射 22 类）** | **37.6%** | **65.0%** | 规则补齐，"其他"降到 16 条 |
| BERT v1（16 类/4ep） | acc 25.7% | F1 4.7% | 小类学不动 |
| BERT v2（10 类/8ep/加权） | acc 28.7% | F1 5.8% | 标签噪声拖累 |
| BERT v3（10 类/新映射/8ep/加权） | acc 21.0% | F1 21.0% | Kaggle 5 折；加权后 acc 换 macroF1 |

## 核心发现

1. **粒度决定成败**：机构名粒度（854 类、84.8% 单例）理论上限仅 15.2%；同一职能在不同城市是不同机构（gold=市体育局 vs pred=林口县教育体育局）。
   → **归口必须两级**：城市（可从留言对象/属地免费提取）+ 职能（学习任务）。

2. **标签质量 > 模型质量**：仅修复职能映射规则（"其他"270 → 16 条），检索式 baseline 从 24.2% → 37.6%（+13.4pt）。监督学习前先审计标签质量。

3. **小样本下检索式 > BERT 微调（v0.3 新结论）**：
   - 检索式 Top-1 37.6% 仍是最优；BERT 加权/不加权均未超过
   - 原因：检索式天然利用"相似留言→相似部门"的历史案例信号，政务归口高度依赖案例相似性
   - 启示：归口模块以检索式为主干；BERT 分类器留待 33 万全量数据（免费标签）再验证

4. **映射规则要点**（scripts/dept_rules.py，训练/评测/notebook 三处共用单一来源）：
   - 区县政府/新区/开发区/管委会/书记/信访 → 党委政府办（513 条，47%——数据现实）
   - "镇/街道/乡镇" → 街道乡镇；"城乡管理" → 城管执法；"回复组/营商" → 政务热线
   - 职能关键词优先，行政区划兜底（顺序敏感）

## 附录：33 万职能分类基线（v0.4）

> 2026-08-16 · `scripts/eval_dept_33w.py` · TF-IDF(char 2-3) + LightGBM · CPU 可跑

**结果（8 类职能，n_test=12000）**：

| 指标 | 数值 |
|---|---|
| **Top-1 acc** | **50.6%** |
| **Top-3 acc** | **80.7%** |

**按职能 Top-1**：
| 职能 | n | acc |
|---|---|---|
| 党委政府办（占 47%） | 5738 | **90.0%** |
| 交通 | 333 | 28.8% |
| 公安司法 | 551 | 24.1% |
| 政务热线 | 954 | 19.3% |
| 街道乡镇 | 1090 | 14.4% |
| 其他 | 1363 | 12.1% |
| 民政 | 1018 | 11.7% |
| **住建** | 953 | **6.0%** |

**结论 & 关键发现**：
1. 相比 1200 条的 37.6%，33 万全量把职能 Top-1 提到 **50.6%**——杠杆名不虚传
2. **类别可分性差是 85% 的真正瓶颈**：住建/民政/街道等类在字面特征上高度重叠（"小区/道路/物业/房屋"在这些类间反复出现），不是纯数据量能解决
3. **发现被遗漏的免费特征**：模型只用"留言内容"，但 33 万 CSV 里有 **`留言领域`**（城建/交通/环保…）——**与职能强相关且全量都有**。把领域作为特征，Top-1 有大幅跳升空间，是下一步最直接的杠杆
4. **环境坑**：sklearn 1.9 分类器在此环境崩溃（numpy 2.4 兼容），已改 **LightGBM**（可跑且更快）

**对"归口 acc 85%"的评估**：50.6% 是真实起点；想冲 85% 需 ①加"留言领域"免费特征 ②或换 BERT embedding（Kaggle GPU）③或收敛到类间差异更大的类别体系。85% 是冲刺目标，不是必然达成——用真实数字说话。
