# 政务留言智能治理助手 —— 项目规划（v0.2）

> 数据策略：1200 条 LLM 标注样本（12 月 × 100，已完成）+ 33 万 CSV 现成标签（免费）

---

## 1. 项目定位

**一句话**：基于人民网领导留言板 **33.3 万条**真实留言（2025 全年），构建**多智能体政务治理助手**——从群众留言到部门归口、回复生成、质量门控、人工复核的全链路系统，所有核心能力模块都有**真实监督信号**和**可量化评测指标**。

**简历叙事（目标态）**：

> 基于人民网领导留言板 33.5 万条真实留言构建多智能体政务治理助手：感知分类→责任部门归口→历史案例 RAG→回复生成→满意度预测+Self-Consistency 双重质量门控→人工复核。部门归口 Top-1 准确率 8x%，回复满意度预测 AUC 0.7x，单条端到端处理 <30s，成本 <0.1 元/条。

## 4. 系统架构

```
群众留言
  │
  ▼ 感知层    类型/领域/紧急度分类          ← 有标签，可评测
  ▼ 归口层    责任部门预测（Top-1/3）        ← 29.5万条标签，检索式+模型
  ▼ 检索层    相似历史案例 RAG（33万语料）    ← 混合检索+重排+引用溯源
  ▼ 生成层    回复建议（引用真实条例/案例）    ← 防幻觉：无出处不生成
  ▼ 质检层    满意度预测 + Self-Consistency 门控
  │          pass → 定稿
  │          retry → 重写（限次）
  │          escalate → 人工复核
  ▼ 人工复核  修改/放行/驳回（记录 diff）     ← 审计
  ▼ 落库      trace 全量审计 + 飞轮回流
```

**现状盘点**（已有骨架，需升级）：
- ✅ 多智能体编排（plan→execute→replan→gate→human_review，LangGraph）
- ✅ 动作白名单 + 预算控制（app/harness/）
- ✅ Self-Consistency 门控（app/quality/）
- ✅ 混合检索 BM25+向量（app/rag/，向量默认关）
- ✅ SQLite 记忆 + trace（app/storage/）
- ⚠️ 数据底座是 201 条样例 → **换成 33 万条真实数据**
- ❌ 无评测框架、无归口/满意度能力模块、无引用溯源、无内容安全

## 5. 任务体系与评测指标

| 任务 | 标签来源 | baseline → 进阶 | 指标 | 目标 |
|---|---|---|---|---|
| 类型分类 | 留言类型(33万) | jieba+TF-IDF+LightGBM → BERT(已有) | Macro-F1 | >0.9 |
| 领域分类 | 留言领域(33万) | 同上 | Macro-F1（长尾加权） | >0.8 |
| **事件分类** | event_type/event_category(1200, 已有) | **BERT 已训好**（event_classifier） | Macro-F1 | 已出数 |
| **紧急度分级** | urgency(1200, 已有) | BERT 三分类（紧急/一般/建议） | F1 | >0.85 |
| **NRE 实体抽取** | 手工标注(已有 5 折模型) | 地点/诉求对象抽取 | F1 | 已出数 |
| 部门归口 | 回复组织(29.5万) | 城市+职能检索式 → 分类 | Top-1/Top-3 | T1>0.75 |
| 回复生成 | 回复内容(29.5万) | RAG+LLM，引用溯源 | 人工可采纳率 | >0.6 |
| 满意度预测 | 满意情况(5.9万) | 文本特征+LightGBM → BERT | AUC | >0.7 |

**论文任务设计**（导师 NLP 方向，同数据双产出）：
1. 事件分类 + 紧急度分级（1200 标注，BERT 已有模型）→ 立即可写
2. NRE 实体抽取（1200，5 折模型已有）→ 立即可写
3. **部门归口预测**（29.5 万免费标签，大规模实验，论文硬通货）
4. **满意度预测**（5.9 万免费标签，AUC）
5. 时空分析（供暖/物业月度分布——季节性治理问题，已有图表）

**归口任务的关键设计**：回复组织是 3 万+ 类别（长尾到单例），直接多分类不可行。
方案：**两级结构**——先定"城市/区县 + 职能类型"，再映射到部门清单；或转成检索问题（留言 → 在"部门职责知识库+历史办理记录"中检索最相似），用 Top-K 检索评估。

## 6. 无 GPU 技术路线

| 组件 | 选型 | 说明 |
|---|---|---|
| 分类 baseline | jieba + TF-IDF + LightGBM | CPU 秒级~分钟级，先出数字再谈模型 |
| 向量化 | 云端 embedding API（一次性 33 万条约几十元）或本地 bge-small-zh-v1.5 ONNX int8 | 两者都无 GPU |
| 向量库 | Qdrant / pgvector（docker） | 十万级起 SQLite 不够 |
| LLM | 云端 DeepSeek/Qwen API 为主 + 本地 Ollama 兜底 | 单条约 5~8 次调用，<0.1 元 |
| 小模型微调 | 魔搭/Colab 免费 GPU 额度，Qwen2.5-1.5B LoRA | 研究型任务，非主线 |
| 重排 | bge-reranker（可选） | recall 达标后再加 |
